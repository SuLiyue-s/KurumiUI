二、进度 ↔ 时钟指针映射（纯函数 handsAt 计算）

进度不是直接转角度，而是先映射成「时间」再算角度：0% = 0 时 0 分（12 点位置），100% = 12 时 0 分（同样 12 点位置）； 12.5% = 1:30，25% = 3:00，50% = 6:00，75% = 9:00。时针按 12 小时整圈走，分针每 60 分钟转一整圈。

三、JSON 驱动：只拿加载层单独渲染（registry / renderNode）

下面三块没有用 create()，而是让 registry 渲染节点：KUI.renderNode({ type: 'boot', props: {...} })。 组件可以被单独取出来用 —— 这正是「可自由拆解 / 组装」的要求：加载层不依赖 app-shell、菜单、标签，只依赖 base.css + boot.css。

四、API 与配置字段

静态 API（KUI.bootLayer.*）

方法说明
create(host, props)手动创建实例（不占用 #kui-boot），返回实例 API
attach(props)接管页面静态骨架或创建单例 #kui-boot
configure(patch)对单例做二次配置（bootstrap 读 app.json 后调用）
instance()取当前单例实例
handsAt(percent)纯函数：进度 → 指针角度 / 时钟读数
destroy()销毁单例并移除节点

实例 API（create/attach/instance 的返回值）

方法说明
setProgress(p)0..100，同时驱动表盘、进度条、百分比与时钟读数
setStep(n)按 stages 里的 step 设文案 + 进度
setText(s) / setMeta(obj)改当前文案 / 标题副标题
configure(patch)运行时改配置（表盘尺寸、指针模式…）
done() / hide() / show()完成淡出 / 隐藏 / 重新显示
error(msg, detail)切换为失败卡片（带重试按钮）
getState()返回 { progress, step, visible, mode, clock… }

配置字段：clock.enabled/mode(progress|spin|none)/size/ticks/smooth、 bar.enabled/mode(progress|indeterminate)、meta、title/subtitle/text、 stages[{ step, text, progress }]、mode(fullscreen|inline)、hideDelay。 文案也可以放在 config/text.json 的 boot.* 里。

五、拆掉 / 单独用加载层

  • 拆掉加载层：把 src/components/boot.js 从 config/kui-modules.json 移除并重新 npm run build:config 即可。bootstrap 会退回到 index.html 里的静态骨架（setBootText / setBootStep / hideBoot 的 legacy 分支），功能不受影响。
  • 只在某个页面用：只引入 base.css + boot.css 和 boot.js 所在入口，然后 KUI.bootLayer.attach()；不需要菜单 / 标签 / app-shell。
  • 换掉默认样式：所有尺寸与颜色都走 --kui-* token 和 --kui-boot-size / --kui-boot-ticks / --kui-boot-progress，覆盖 CSS 变量即可，无需改组件代码。
  • 真实首屏接入：src/app/bootstrap.js 在启动第一步 attachBootLayer()，读完配置再 configureBootLayer()，四个阶段与 app.json 的 boot.stages 一一对应。
