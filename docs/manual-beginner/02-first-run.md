# 02 · 第一次运行

> 适用版本：KurumiUI v1.4.1 ｜ 难度：⭐ 入门 ｜ 前置章节：[01-setup](01-setup.md) ｜ 阅读时长：约 20 分钟

## 本章目标

- 用两种方式把 KurumiUI 下载到电脑：`git clone`，或在网页上下载 ZIP 压缩包。
- 学会在命令行里进入项目文件夹，并用 `npm start` 启动项目，在浏览器打开 `http://127.0.0.1:8080/`。
- 认识启动屏和主界面的几个区域，知道怎么停止服务器、端口被占用时怎么办。
- 学会另一种打开方式：双击 `index.html`（`file://` 模式），并理解它为什么要先构建。
- 修改第一个配置——把界面标题换成你自己的名字，并在两种模式下都看到变化。

> 读完并做完本章练习，你就完成了「把项目跑起来 + 改出第一处不同」这件事。下一章 [03-tour.md](03-tour.md) 会带你逐个区域认识界面。

---

## 1. 把项目拿到电脑上（两种方式，任选一种）

KurumiUI 是一个网页项目，源码在 GitHub 上。你需要先把整个项目文件夹下载到自己的电脑。两种方式效果一样，任选一种：

| 方式 | 需要什么 | 优点 | 适合 |
| --- | --- | --- | --- |
| ① `git clone` | 01 章装好的 Git | 以后更新项目方便 | 想长期使用、想跟着项目更新 |
| ② 下载 ZIP | 只要浏览器 | 不用装 Git，操作简单 | 只想先把项目跑起来看看 |

### 方式一：用 `git clone` 克隆（推荐）

打开命令行（Windows 用 PowerShell，macOS 用「终端」），输入下面其中一条命令：

```bash
# HTTPS 方式（不需要提前配置任何密钥，推荐新手用这条）
git clone https://github.com/SuLiyue-s/KurumiUI.git
```

```bash
# SSH 方式（电脑上已经配置过 GitHub 的 SSH 密钥时可用）
git clone git@github.com:SuLiyue-s/KurumiUI.git
```

> 你会看到：命令行开始输出下载进度，最后出现类似 `Receiving objects: 100% ... done.` 的内容。下载完成后，当前文件夹里会多出一个 `KurumiUI` 文件夹。
>
> 如果卡住不动或提示连接失败，多半是网络问题；也可以改用下面的「方式二」直接下载 ZIP。命令里的地址只是下载项目，不会修改远端仓库。

### 方式二：在网页上下载 ZIP（不装 Git 也能用）

1. 浏览器打开项目主页：<https://github.com/SuLiyue-s/KurumiUI> 。
2. 点页面右上角绿色的 **Code** 按钮，在弹出菜单里选 **Download ZIP**。
3. 下载完成后解压。解压出来的文件夹可能叫 `KurumiUI-main`（名字后面的 `-main` 是分支名，不影响使用）。
4. 把解压后的文件夹放到一个你容易找到的位置，例如桌面或「下载」文件夹。

> 说明：无论用哪种方式，你拿到的都是**源码**。有两个文件是「用源码自动生成」的，不会被放进下载包里，所以新下载的项目里暂时看不到它们，这是正常的，下一节会生成。

## 2. 打开项目文件夹

接下来的命令都要**在项目文件夹里**执行。先进入这个文件夹：

```bash
# 进入项目文件夹（如果你的文件夹叫 KurumiUI-main，就写 KurumiUI-main）
cd KurumiUI
```

> 你会看到：命令行的提示符变了，说明你已经「站」在项目文件夹里。

用下面任意一条命令确认自己没有走错地方：

```bash
# Windows
dir
```

```bash
# macOS
ls
```

> 你会看到类似这样的内容：`index.html`、`package.json`、`server.js`、`src`、`config`、`pages`、`standalone`、`tools`、`README.md` 等。只要能看到 `index.html` 和 `package.json`，就说明对了。
>
> 如果 `dir` / `ls` 显示的完全不是这些东西，说明你还在别的文件夹。用 `cd ..` 退回去，重新 `cd` 到项目文件夹。

> 小技巧：Windows 可在文件夹地址栏输入 `powershell` 回车，直接在该文件夹打开命令行；macOS 可把文件夹拖进终端窗口，路径会自动填好。

## 3. 方式 A：用 `npm start` 启动（推荐日常使用）

### 3.1 先说明：不需要 `npm install`

很多前端项目下载后的第一步是 `npm install`，但 **KurumiUI 不需要**：它没有任何第三方依赖（项目里的 `package.json` 没有 `dependencies` 字段），本地服务器和工具只用 Node.js 自带的能力。所以：

- 不用联网下载依赖包；
- 不用等 `npm install` 跑完；
- 直接 `npm start` 就能启动。

### 3.2 启动

在项目文件夹里输入：

```bash
npm start
```

> 第一次启动时，项目会先自动检查并生成两个「初始化文件」（`config/bundle.js` 和 `src/core/kui-all.js`），所以会多等一两秒。你会看到类似这样的内容（版本号、路径以你的电脑为准）：
>
> ```text
> > kurumi-ui@1.3.8 start
> > node server.js
>
>   KurumiUI · 刻刻帝终端
>   ────────────────────────────────────────────
>   本地地址: http://127.0.0.1:8080/
>   根目录  : 你的项目文件夹路径
>   Node    : v20.x.x
>   停止服务: Ctrl + C
> ```
>
> 前两行是 npm 在打印正在执行的命令，不用管；最关键的是 **本地地址** 那一行。

### 3.3 在浏览器里打开

打开浏览器，在地址栏输入（或直接点开）命令行里显示的地址：

<http://127.0.0.1:8080/>

> 你会看到：先出现一个深色的启动屏（通常不到 1 秒），然后进入主界面。地址栏变成 `http://127.0.0.1:8080/`，浏览器标签页的标题变成「刻刻帝终端」。

> 小知识：`127.0.0.1` 表示「你这台电脑自己」，`8080` 是端口号。这个服务器只在你自己的电脑上运行，不会把项目发布到互联网。

### 3.4 停止服务器

在运行 `npm start` 的那个命令行窗口里，按 **`Ctrl + C`**（Windows 上如果一次没反应，可以再按一次或按 `Y` 再回车）。看到命令提示符重新出现，就说明服务器已停止。

这时再刷新浏览器，页面就打不开了——这是正常的，因为本机服务器已经停了。想继续看，就再 `npm start` 一次。

### 3.5 端口被占用怎么办

端口（例如 8080）就像「门牌号」，同一时间只能被一个程序使用。如果 8080 已经被别的程序占用，启动时会看到这样一行提示，然后服务器会自动换到下一个端口继续尝试：

```text
端口 8080 已被占用，正在尝试 8081
```

> 看到这行不用慌：往下看「本地地址」那一行，它实际显示的是哪个端口（例如 `http://127.0.0.1:8081/`），在浏览器里用那个地址访问即可。

如果你想主动换一个端口启动，有两种写法：

```bash
# 写法一：直接运行服务器脚本并指定端口（最直观）
node server.js --port 9000
```

```bash
# 写法二：通过 npm start 把参数传给服务器脚本（注意中间的两个减号）
npm start -- --port 9000
```

> 两种写法效果一样，启动后「本地地址」会变成 `http://127.0.0.1:9000/`。想查看服务器支持的全部参数，可以运行 `node server.js --help`，它会打印一行用法说明。

### 3.6 第一次成功画面：逐区认识

主界面可以分成 5 个区域，从上到下、从左到右看：

1. **启动屏（一闪而过）**：全屏深色背景（星芒、光环、表盘），中央是大号表盘和指针，标题「KurumiUI」、一行副标题，下方是细进度条和一行文字「正在加载界面配置…」。这行文字会依次变成「正在应用界面风格…」「正在构建界面…」「结界已就绪」，然后启动屏消失。
2. **左侧菜单**：最上方是品牌区（「刻刻帝终端」+「KURUMIUI · 灵装回路」），中间是按分组排列的菜单项（时间中枢、灵装回路、观测回廊、刻印结界），底部显示「灵装回路」、版本号、一行版权信息和一个「切换灵装主题」按钮。
3. **顶部导航栏**：左边是「收起菜单」按钮，接着是标题「刻刻帝终端」和副标题「灵装回路 · 时间结界控制台」、面包屑「刻刻帝终端」；右边是后退 / 前进 / 刷新 / 全屏四个小按钮，以及「检索」「提醒（带数字角标）」「设置」「主题」四个动作按钮。
4. **标签栏**：一个固定的「刻刻帝终端 · 首页」标签、一个「未保存数据验证」标签，当前选中的是「主题灵装」标签。点标签可以切换内容，标签右侧的 × 可以关闭。
5. **内容区**：默认显示「主题灵装」页面——6 张主题卡片（绯红刻刻帝、白羽灵装、星夜观测、樱雾通灵、深渊刻印、黎明绯光）和下方的主题色板。

> 界面左下角/右下角还有头像、齿轮等装饰元素，部分可点。完整说明见 [03-tour.md](03-tour.md)。

## 4. 方式 B：双击 `index.html` 直接打开（`file://` 模式）

除了 `npm start`，你还可以像打开普通网页一样，**双击 `index.html`** 直接看界面。这种方式不需要命令行一直开着，适合把项目打包发给别人预览。但它有一个前提：**先构建一次**。

### 4.1 为什么需要先构建

浏览器出于安全考虑，不允许网页随意读取你电脑上的本地文件。`file://` 模式下，页面不能像在服务器上那样直接读取 `config/app.json` 这些配置文件，所以项目会把配置**打包成一份 JavaScript 文件**（`config/bundle.js`），让页面直接加载。这个打包动作就是「构建」。

在项目文件夹里运行：

```bash
npm run build:config
```

> 你会看到类似下面的输出（数字可能略有不同）：
>
> ```text
> KurumiUI 配置打包完成
>   输出: config/bundle.js
>   大小: 112.5 KB
>   app.json   : ✔
>   text.json  : ✔
>   themes.json: ✔
>   demos      : 11 个
> [build-all] 已生成 src/core/kui-all.js (4032 字节)
> [build-all] profiles: app=29, standalone=28
> ```
>
> 看到「配置打包完成」和几个 ✔，就说明构建成功。这条命令名字叫 `build:config`，但它实际会同时生成两个文件：`config/bundle.js`（配置包）和 `src/core/kui-all.js`（页面加载用的脚本清单）。这两个文件都是自动生成的，不需要你手动修改，也不建议提交到 Git 仓库。

### 4.2 双击打开

1. 在文件资源管理器（macOS 是访达）里打开项目文件夹。
2. 找到 `index.html`，双击它（或右键 →「打开方式」→ 选择 Chrome / Edge / Firefox）。
3. 浏览器地址栏会显示以 `file:///` 开头的地址，稍等片刻，界面应该和用 `npm start` 时一样。

> 如果双击后停在启动屏、白屏或提示「配置读取失败」，最常见原因是**还没构建**（新项目里没有 `config/bundle.js`），或构建那一步报错了。回到 4.1 重跑命令，成功后再刷新。

## 5. 改你的第一个配置

现在我们把界面上的名字换成你自己的。要改的文件只有一个：`config/app.json`。

### 5.1 先找到要改的三个位置

界面上的「名字」不止一处，分别由三个字段控制。只改其中一个，只有对应位置会变，所以第一次练习要把三处一起改：

| 配置文件里的位置 | 界面上对应的位置 |
| --- | --- |
| `app.title` | 浏览器标签页的标题（地址栏上方） |
| `menu.props.brand.title` | 左侧菜单最上方的品牌名 |
| `menunav.props.title` | 顶部导航栏里的标题文字 |

> 用 VS Code 打开项目文件夹后，打开 `config/app.json`，按 `Ctrl + F`（macOS 是 `Command + F`）搜索 `"title"`，就能快速定位到这几处。

### 5.2 改前与改后

这是 `config/app.json` 里相关内容的摘录（改前）：

```json
{
  "app": {
    "name": "KurumiUI",
    "title": "刻刻帝终端",
    "subtitle": "灵装回路 · 时间结界控制台"
  },
  "menu": {
    "type": "menu",
    "props": {
      "brand": {
        "title": "刻刻帝终端",
        "subtitle": "KurumiUI · 灵装回路"
      }
    }
  },
  "menunav": {
    "type": "menunav",
    "props": {
      "title": "刻刻帝终端"
    }
  }
}
```

把三处 `title` 的值改成「我的第一个界面」（只改双引号里的文字）：

```json
{
  "app": {
    "name": "KurumiUI",
    "title": "我的第一个界面",
    "subtitle": "灵装回路 · 时间结界控制台"
  },
  "menu": {
    "type": "menu",
    "props": {
      "brand": {
        "title": "我的第一个界面",
        "subtitle": "KurumiUI · 灵装回路"
      }
    }
  },
  "menunav": {
    "type": "menunav",
    "props": {
      "title": "我的第一个界面"
    }
  }
}
```

> 重要提醒：
>
> - 上面两段是为了让你看清楚结构而**摘出来的片段**，实际文件里这三段并不挨在一起，不要整段复制粘贴进去，只按字段名找到位置、改双引号里的文字。
> - 只改双引号里的中文内容，不要动引号、逗号、花括号；JSON 里不能写注释，最后一项后面也不能多写逗号。
> - 改完一定要**保存**（VS Code 里按 `Ctrl + S`；标签页上的小圆点消失就表示已保存）。

### 5.3 保存后怎么让它生效

| 打开方式 | 改完配置后要做什么 |
| --- | --- |
| 方式 A：`npm start`（`http://127.0.0.1:8080/`） | 直接刷新浏览器即可（`F5`，或 `Ctrl + R` / `Command + R`）。如果没变化，按 `Ctrl + F5` 强制刷新 |
| 方式 B：双击 `index.html`（`file://`） | 先运行一次 `npm run build:config`，成功后再刷新浏览器 |

### 5.4 你会看到

刷新后：浏览器标签页标题、左侧菜单品牌名、顶部导航栏标题，三处都变成了「我的第一个界面」。界面的布局、颜色、菜单项都没有变——这次只改了「名字」。

> 如果你只改了 `app.title` 这一处，会发现**只有浏览器标签页标题变了**，左侧品牌和顶栏还是「刻刻帝终端」。这不是没生效，而是因为那两处各有自己的 `title` 字段。这也是新手最喜欢踩的坑：**改配置要看清楚字段对应的是界面哪一处**。

## 6. `http://` 与 `file://` 两种模式的区别

| 对比项 | 方式 A：`npm start`（`http://`） | 方式 B：双击 `index.html`（`file://`） |
| --- | --- | --- |
| 怎么打开 | 命令行运行 `npm start`，浏览器访问本地地址 | 双击文件，浏览器直接打开 |
| 配置从哪里读 | 每次都直接读最新的 `config/*.json` | 读打包产物 `config/bundle.js` |
| 改配置后 | 刷新即生效 | 需先 `npm run build:config`，再刷新 |
| 适合场景 | 日常修改配置、看效果 | 把项目发给别人离线预览、不想开命令行 |
| 需要命令行吗 | 需要（服务器要保持运行） | 不需要 |

> 两种方式看到的是**同一套界面**，只是「读取配置的方式」不同。日常改配置推荐用方式 A，改一下、刷新一下就能看到效果；要发给别人时，用方式 B 或 [08-deploy.md](08-deploy.md) 里介绍的静态托管方式。

## 7. 常见失败与处理

| 现象 | 最可能的原因 | 先做这三步检查 | 处理 |
| --- | --- | --- | --- |
| 双击 `index.html` 后一直停在启动屏、白屏，或提示配置读取失败 | 新下载的项目没有 `config/bundle.js`，还没构建 | ① 确认命令行在项目文件夹里 ② 运行 `npm run build:config` ③ 看到「配置打包完成」后刷新 | 按 4.1 构建成功后刷新；以后每次改配置都要重新构建 |
| 输入 `npm start` 提示「'npm' 不是内部或外部命令」或「command not found」 | Node.js 没装好，或装完没重新打开命令行 | ① 运行 `node -v` 看有没有版本号 ② 关掉命令行重新打开 ③ 再看 `npm -v` | 回到 01 章第 3 节重新安装 Node.js，装完务必重开命令行 |
| `npm start` 运行了，但浏览器打不开或一直转圈 | 服务器没启动成功，或访问的地址/端口不对 | ① 看命令行是否出现「本地地址」 ② 访问的地址是否和它完全一致 ③ 关掉代理/换浏览器再试 | 以命令行打印的地址为准；如果提示端口被占用，用实际尝试到的新端口 |
| 启动时提示「端口 8080 已被占用，正在尝试 8081」 | 8080 被其它程序占用（服务器会自动换端口） | ① 看「本地地址」实际端口 ② 用实际端口访问 ③ 或主动换端口启动 | 用新端口访问即可；想固定用 `node server.js --port 9000` |
| 改了 `config/app.json` 刷新后没变化 | 改错文件、没保存，或 `file://` 模式没重新构建 | ① 看编辑器标题栏有没有未保存的小圆点 ② 确认改的是项目里的 `config/app.json` ③ 确认打开方式 | 保存文件后，`http://` 模式刷新；`file://` 模式先 `npm run build:config` |
| 页面中文显示为乱码 | 文件保存编码不是 UTF-8 | ① VS Code 右下角查看编码 ② 点击编码改成 `UTF-8` ③ 保存并刷新 | 用 VS Code 另存为 UTF-8；不要用会改动编码的旧编辑器 |

## 动手练习

1. **换端口启动**：用 `node server.js --port 9000` 启动项目，在浏览器访问 `http://127.0.0.1:9000/`，确认能看到界面；然后用 `Ctrl + C` 停止，再用 `npm start` 按默认端口启动一次。
2. **两处改名，两种方式各验一遍**：把 5.2 里的三处标题改成「我的第一个界面」并保存。先验证 `npm start` 方式（刷新即可），再换成双击 `index.html` 方式（记得先 `npm run build:config`），两种方式都确认三处名字都变了。
3. **只改一处，观察差异**：把 `app.title` 改成「只改标签页」并保存，另外两处保持「我的第一个界面」。刷新后看看哪些地方变了、哪些没变，把结论记在笔记里。
4. **停掉服务器再刷新**：运行 `npm start` 时按 `Ctrl + C` 停止服务器，再刷新浏览器，观察打不开的提示；重新 `npm start` 后刷新恢复——体会「页面由你电脑上的服务器提供」。

## 本章小结

- 拿到项目有两种方式：`git clone`（需要 Git）或网页下载 ZIP（只需浏览器），效果一样。
- 后面的命令都要**先在命令行里 `cd` 进入项目文件夹**，用 `dir` / `ls` 能看到 `index.html`、`package.json` 就说明位置对了。
- KurumiUI **没有第三方依赖**，不需要 `npm install`；直接 `npm start` 即可。
- `npm start` 会启动本地服务器并自动生成两个初始化文件；浏览器访问 `http://127.0.0.1:8080/` 就能看到界面。
- 停止服务器用 `Ctrl + C`；端口被占用时服务器会自动 +1，也可以 `node server.js --port 9000` 主动换端口。
- 双击 `index.html`（`file://`）也能打开，但**必须先运行 `npm run build:config`**，否则会停留在启动屏。
- 改配置只需编辑 `config/app.json`：`http://` 模式刷新即生效，`file://` 模式要先重新构建再刷新。
- 界面上的名字分散在多个字段里：`app.title` 管浏览器标签页，`menu.props.brand.title` 管左侧品牌名，`menunav.props.title` 管顶部标题；**改配置要改对位置**。
