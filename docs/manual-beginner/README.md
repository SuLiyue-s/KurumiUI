# KurumiUI 小白入门手册

> 适用版本：KurumiUI v1.4.1 ｜ 难度：⭐ 入门 ｜ 前置章节：无 ｜ 阅读时长：约 180 分钟（含动手）

---

## 0. 这是一本什么书

这是一本**写给完全没接触过这个项目的人**的说明书。

你不需要会写代码，不需要懂命令行，也不需要知道什么是 JSON、什么是框架。只要你会用浏览器、会打字、会复制粘贴，就能跟着这本书：

1. 在自己电脑上把 KurumiUI **跑起来**；
2. **看懂**界面上每一块是什么、由哪个文件控制；
3. 改几个配置文件，把它**改成你自己的界面**（名字、菜单、标签页、文案、头像、配色）；
4. **新建一个自己的页面**，并把它挂到菜单里；
5. 做一个最简单的**表单**；
6. 把整套界面**部署到自己的网站或项目**里给别人看。

> 本书只讲「怎么用」。想研究内部实现、完整字段表、扩展框架，请读同仓库的**高级手册**：[`../manual/README.md`](../manual/README.md)。

**你不需要准备的东西**：不需要买服务器、不需要域名、不需要会编程、不需要 `npm install`（这个项目没有第三方依赖）。

## 2. 30 秒先跑起来（先看效果，再读书）

如果你只想「先看看它长什么样」，做完这三步就够了：

```bash
# 1) 拿到项目（二选一）
git clone git@github.com:SuLiyue-s/KurumiUI.git
# 没有 Git？到仓库页面点「Code → Download ZIP」，解压即可

# 2) 进入项目文件夹
cd KurumiUI

# 3) 启动本地服务器（不需要 npm install）
npm start
```

然后在浏览器打开 **http://127.0.0.1:8080** ，你会先看到一个带时钟指针动画的**启动屏**，随后进入主界面：左侧菜单、顶部导航、标签栏、内容区。

- 停止服务器：在命令行窗口按 `Ctrl + C`。
- 8080 被占用：改成 `node server.js --port 9000`，再打开 `http://127.0.0.1:9000`。
- 也可以**不启动服务器**，直接双击项目里的 `index.html`（`file://` 方式）；但这种方式必须先执行一次 `npm run build:config`，详见 [02-first-run.md](02-first-run.md)。

> 打不开、白屏、命令行报错？直接翻 [09-troubleshooting.md](09-troubleshooting.md)，那里按「现象」列了 20 多个常见问题。

**先记住两个结论（后面会反复用到）**：① 改 `config/*.json` 后，用 `npm start` 时刷新页面即生效，只有 `file://` 或“只部署了 bundle”时才必须 `npm run build:config`；② 界面上点的「保存」（终端名称、主题、头像、密度等）只写进**你自己浏览器的 localStorage**，**不会修改配置文件**。完整说明见 [04-config-ui.md](04-config-ui.md) 第 9 节。

## 6. 这本书的写法约定

为了让你少踩坑，本书所有操作都按同一个节奏写：

1. **改哪里** —— 先告诉你打开哪个文件、改哪一行；
2. **改成什么** —— 给出「改前 / 改后」的完整小片段，可以直接复制；
3. **怎么保存生效** —— 保存文件后要不要刷新、要不要执行命令；
4. **你会看到** —— 具体描述屏幕上哪个位置发生了什么变化。

读的时候注意这些标记：

| 标记 | 含义 |
| --- | --- |
| ✅ | 做完这一步应该看到的结果 |
| ⚠️ | 容易做错的地方，先看一眼再动手 |
| 📌 | 记住这条，后面会用到 |
| 💡 | 小技巧，可以跳过 |
| ⭐ | 本章重点 |

两个安全约定（每章都会提醒）：

- **先备份**：改任何配置前，先把原文件复制一份（如 `app.json` → `app.json.bak`），或者确保项目是用 Git 克隆的，改坏了能撤销。
- **只碰两个地方**：小白阶段只改 `config/`（配置）和 `pages/`（页面），**不要改 `src/`**（框架代码）。等你能读懂高级手册 [12-extension.md](../manual/12-extension.md) 再动它。

## 7. 项目文件夹里有什么（只需要认识 6 个）

```text
KurumiUI/                 ← 项目文件夹（你可能叫别的名字）
├── index.html            ← 双击打开的主页面
├── config/
│   ├── app.json          ← 主配置：标题、菜单、标签页、布局…（最常改）
│   ├── text.json         ← 界面上的文字
│   ├── demos/            ← 示例配置（看效果用，不用改）
│   └── bundle.js         ← 自动生成的配置包（file:// 模式靠它）
├── src/
│   ├── themes.json       ← 主题配色（6 套）
│   ├── core/             ← 框架核心代码（不要改）
│   ├── components/       ← 组件代码（不要改）
│   └── styles/           ← 样式（不要改）
├── pages/                ← 7 个业务页面（home、profile、form…）
├── standalone/           ← 12 个单个组件演示页（学控件用）
├── server.js             ← 本地小服务器（npm start 就是跑它）
└── package.json          ← 项目说明 + 命令清单
```

其余文件夹（`test/`、`tools/`、`docs/` 等）是开发与文档用的，**小白阶段可以完全不管**；本项目零依赖，不会生成 `node_modules`。

## 8. 怎么确认一切正常

跑完安装和启动后，用这三条命令自检（在项目文件夹里执行）：

```bash
npm start                 # 应该打印出本地地址，浏览器能打开
npm run check:assets      # 末行应为：汇总: 21 个 HTML，错误 0 个，警告 0 个
npm test                  # 末行应为：汇总: 33 通过 / 0 失败 / 0 跳过
```

三条都对上，说明你的环境、项目、浏览器都没问题，可以安心往下读。

## 10. 版本与维护

- 本手册对应 **v1.3.8**。项目升级后，先看仓库根目录 `CHANGELOG.md` 对应版本段，再回来看本手册是否有变化。
- 本手册与高级手册**互相链接**：小白手册负责「带你进门」，高级手册负责「进门后的全部细节」，两份都要保留。
- 手册改完后建议跑一次自检（零依赖）：

```bash
node tools/check-beginner-manual.js   # 本手册
node tools/check-manual.js            # 高级手册
```

- 发现手册与项目不一致：以**项目实际行为**为准（配置/页面/命令都以仓库里的真实文件为准），并在 `CHANGELOG.md` 对应版本里补一句说明。
